# FactLang 0.1.3 — Improvements Design

Status: DRAFT for approval (cold-read gaps resolved) · Date: 2026-11-25 · Process: Elephant-Goldfish (spec → cold-read → goldfish tasks → reviews → release)
Base: `main` after 0.1.2 (`ea1671b`). Binding parent spec: `docs/specs/2026-11-24-factlang-design.md` (all of it still applies; this document only adds or narrows).

## 1. Intent

0.1.0–0.1.2 shipped the full library. Reviews logged a set of improvements judged "OK to ship / can wait". 0.1.3 lands them. Everything is **backward compatible** (additive API, stricter-but-safer refusals only on the display/inline path, docs, tests, CI), so it ships as a **patch** release inside the `>=0.1.2,<0.2` range the downstream consumer pins. **[call]** A breaking change is out of scope; anything that would break is deferred to 0.2.0.

## 2. Goals / non-goals

Goals: G1 fix the known correctness nits; G2 add two small public helpers downstream code generators asked for; G3 bound the agent/MCP surface; G4 make the test suite and release gate more trustworthy; G5 docs accuracy.
Non-goals: new verbs, new dialects, any change to verdict semantics, any change to bound-parameter SQL.
Anti-goals: changing what an existing passing claim measures; loosening any refusal; a release whose tag commit didn't pass the full OS matrix.

## 3. Changes

### 3.1 Front end and analyser (task T1)
- **F1 Caret alignment with tabs.** `DiagnosticBag.render` reproduces each source line's tabs in the caret line's leading padding (copy `\t` where the source has `\t`, space elsewhere) so carets line up under the offending text in any tab width. Test with a tab-indented claim.
- **F2 Continuation rule documented.** `\` followed only by spaces/tabs before the newline is a continuation (current behaviour). Document it in `docs/reference/grammar.md` (lexical section) and add a `factlang-valid` block exercising it.
- **F3 Temporal VALUE with tolerance is flagged at analysis.** For answer verbs (MIN, MAX), a `VALUE` whose coerced value is temporal combined with `TOLERANCE` or `ABS_TOLERANCE` emits a new **warning** `FL314` "tolerance has no effect on a temporal VALUE; this claim will be ERROR when judged". Warning severity keeps `factlang lint` exit codes and `Report.ok` unchanged (compatibility); judge-time behaviour (ERROR) is unchanged. Implement via a declarative `VerbSpec` rule or a contract-level validator hook — builder's choice, no verb-name if-chain in the analyser. Also in T1 (same file): the analyser test that registers `NAN_T`/`INF_T` removes them in a finalizer.
- **F4 Hash-preserving format property.** Spec §13's property test: for generated valid documents, `semantic_hash` of every claim in `parse(format(x))` equals that of `parse(x)` (analysed with the standard pack and `NullCatalog`).

### 3.2 Inline literal spellings and precision (task T2) — inline/display path only
Per the recorded rule, every change here gets a CHANGELOG "Changed (inline output)" entry.
- **I1 Timestamp literal spelling per dialect.** Fractional seconds follow the existing `LiteralStyle` contract (`.ffffff` only when microseconds ≠ 0). Native `trino` (its timestamps are `timestamp(6) with time zone`): `TIMESTAMP 'YYYY-MM-DD HH:MM:SS[.ffffff] UTC'` — space separator, explicit `UTC` zone so the value means UTC regardless of session zone. Native `databricks`: `TIMESTAMP 'YYYY-MM-DD HH:MM:SS[.ffffff]'` (naive UTC, existing rule). Bridge: add a new explicit table `BRIDGE_LITERAL_STYLES` in `sql/sqlglot_bridge.py` keyed by sqlglot dialect name, consulted after native profiles and before the ancestor walk: `presto`, `athena` → the trino form (with ` UTC`); `hive`, `spark`, `spark2`, `teradata`, `exasol` → `TIMESTAMP 'YYYY-MM-DD HH:MM:SS[.ffffff]'` (naive UTC). The table never overrides the quote-doubling decision (always from the dialect's lexer). Date literals unchanged. Each verified by `sqlglot.parse_one(..., read=d)` round-trip; DuckDB executes the ANSI form. All of this is one CHANGELOG "Changed (inline output)" entry listing every dialect whose spelling changed.
- **I2 Booleans where TRUE/FALSE are not literals.** `teradata` (bridge table entry) inlines `1`/`0` (as T-SQL/Oracle do). Verified via sqlglot.
- **I3 Precision caps.** Inlining refuses with `FL507` a `Decimal` whose plain-notation precision (integer digits + scale, i.e. what DECIMAL(p,s) must hold; `Decimal('1E+50')` counts 51) exceeds 38, or an `int` outside the signed 64-bit range, or a `float` whose `repr` has more than 17 significant digits (cannot happen for finite floats — assert-only). Reason: engines silently change type/precision beyond these (measured: DuckDB DOUBLE/VARCHAR). Bound parameters are unaffected.

### 3.3 Public helpers and API hygiene (task T3)
- **P1 `factlang.syntax.needs_quoting(name: str) -> bool`.** True iff writing `name` bare in FactLang source would not denote that exact name: it does not match `[A-Za-z_][A-Za-z0-9_$]*`; or it contains at least one letter and no lowercase letter (an uppercase bare word starts the attribute section / is read as a keyword); or it equals `WHERE`, `USE`, or a member of `FILTER_KEYWORDS` (case-sensitive). Note: `deleted`, `Status`, `order` → False; `ID`, `NULL`, `order items`, `2fa` → True.
- **P2 `factlang.syntax.quote_name(name: str) -> str`.** Returns the FactLang double-quoted form (`"` + name with `"` doubled + `"`); refuses (ValueError) an empty name and a name containing `\r`, `\n` (the lexer can't represent them) or NUL (no warehouse identifier can hold it; the SQL printer would refuse it as FL502). Property test: for arbitrary printable names, `parse_filter(f'{quote_name(n)} IS NULL')` yields an `FIsNull` whose column is `Ident(n, quoted=True)`.
- Both added to `factlang.syntax.__all__`, the `docs/reference/api.md` stable table, and SemVer-stable.
- **P3 `fl.ir.unregister_primitive(cls) -> None`** added (KeyError if absent) and documented as the supported way to remove a registration; tests switch from `PRIMITIVE_LOWERINGS.pop(...)` to it. `PRIMITIVE_LOWERINGS` stays a mutable dict in 0.1.x (making it read-only would break `.pop` callers) and is documented as read-only-by-convention; the read-only view is deferred to 0.2.0.
- **P4 No behaviour-bearing `assert` in `src/`.** Scope: asserts whose removal under `python -O` could change an outcome or turn a clean error into a later, worse one (type-narrowing guards on values from callers, catalogs, drivers or plans — e.g. `CachedCatalog`). Pure internal invariants (unreachable-state checks) may stay. Each converted site raises the same exception class a caller would see today (or the documented error). A test runs the DuckDB verb matrix fixture once normally and once under `python -O` (subprocess) and asserts identical outcomes.

### 3.4 Agent / MCP bounds (task T4)
- **A1 Claim cap.** `handle_tool_call` and the MCP server refuse a `factlang_check` / `factlang_explain` call carrying more than `max_claims` claims with a stable error code `too_many_claims`, BEFORE any analysis or SQL. Count = lines that are neither blank, comment-only, nor a `USE` directive, after joining `\` continuations (no analysis needed). Adding the code is additive: the docs state that tool error codes may be added in patch releases and consumers must handle unknown codes; default `max_claims=200`, configurable via `factlang mcp --max-claims N` and a `handle_tool_call(..., max_claims=...)` keyword. Lint is not capped (no SQL runs).
- **A2 Docs.** `docs/agents.md` + wiki Agent-Integration: run the server under a read-only database role; `--max-bytes` only bounds cost on dry-run-capable connectors; `--max-claims` bounds work.

### 3.5 Tests, CI, release gate, docs nits (task T5)
- **C1 Release gate on the full matrix.** `release.yml` verify waits for the CI run triggered by the tag push (event `push`, `head_branch` == the tag name, same sha) and passes only if that run concluded `success` with every `test-full` matrix leg `success`; no other run may substitute. Wait budget 100 minutes including queueing; the verify job's `timeout-minutes` becomes 120.
- **C2 Timing-robust tests.** `tests/unit/test_engine.py` timeout/"fast" cases and `tests/unit/connectors/test_dbapi_threads.py` use events/barriers or generous budgets (≥10× the expected time) so loaded Windows runners can't flake them; no test asserts an upper bound under 1 s.
- **C3 Test hygiene.** `tests/test_architecture.py` reports each violation once; `tests/unit/packs/packs_helpers.py`'s `sys.path` hack is replaced by a `tests/conftest.py`-level fixture or a proper importable helper module.
- **C4 Docs nits.** `docs/guide/verbs.md` says "19 verbs" in digits and its group descriptions cover all 19; a doc test asserts the number in that sentence equals `len(standard_pack().names())`; `docs/extending/connectors.md` already notes the lock fallback — add that non-weak-referenceable connections (sqlite3, pyodbc) are held for the process lifetime and how to avoid it (reuse one connector per connection).

### 3.6 Release (task T6)
Version `0.1.3`; CHANGELOG `[0.1.3] - <date>` with Added / Changed (inline output) / Fixed / Tests & CI sections; tag `v0.1.3`; Trusted Publishing; verify PyPI + fresh install; notify the downstream consumer.

## 4. Approaches considered
1. **One patch release (0.1.3) with only compatible changes** — chosen **[call]**: downstream pins `<0.2`, so they get everything immediately.
2. 0.2.0 with the same content — no reason to force consumers to re-pin; nothing here breaks.
3. Split into several patches — more release overhead, no benefit.

## 5. Process (EGM)
This spec is cold-read by a fresh agent before approval. Tasks T1–T5 are independent (disjoint files except CHANGELOG, which only T6 writes; T3's switch of `PRIMITIVE_LOWERINGS.pop` callers touches `tests/unit/sql/test_lower.py` and `tests/unit/ir/test_primitives.py`, which T2 must not edit) and run as parallel goldfish in private worktrees; each gets a fresh reviewer; T6 releases after all are approved, then one whole-diff review before tagging.
